# 要件定義書

## 概要

この機能は、アービトラージボットが発見した裁定取引機会をJSONL形式で記録し、HTTPエンドポイント経由でデータを取得できるデータストレージ・API システムを実装します。このシステムにより、ボットは裁定取引チャンスの記録（通貨ペア + 発見時刻）を永続的に保存し、分析・監視目的で軽量なAPI経由でデータを公開できるようになります。

## 要件

### 要件 1

**ユーザーストーリー:** アービトラージボットの運用者として、裁定取引機会の記録をJSONL形式で保存したい。これにより、発見したすべての機会の永続的なログを分析用に維持できる。

#### 受け入れ基準

1. 裁定取引機会が検出された時、システムはarbitrage.jsonlファイルに新しい記録を追記する
2. JSONLファイルに書き込む時、システムは{"pair": "SYMBOL/SYMBOL", "timestamp": "ISO8601_STRING"}の形式を使用する（timestampはJST（日本標準時、UTC+9）のISO8601形式で記録すること）
3. arbitrage.jsonlファイルが存在しない時、システムは自動的にファイルを作成する
4. 記録を追記する時、システムはデータ破損を防ぐためアトミックな書き込みを保証する
5. タイムスタンプを保存する時、システムはUTCタイムゾーンのISO 8601形式を使用する

### 要件 2

**ユーザーストーリー:** 開発者またはアナリストとして、HTTP API経由でアービトラージデータを取得したい。これにより、取引機会を分析し、ボットのパフォーマンスを監視できる。

#### 受け入れ基準

1. GET /arbitrage-dataをリクエストした時、システムはすべての記録をJSON配列として返す
2. GET /arbitrage-data/rawをリクエストした時、システムは生のJSONLファイル内容をプレーンテキストとして返す
3. JSONLファイルが空または存在しない時、システムは/arbitrage-dataに対して空の配列を返す
4. JSONLファイルが空または存在しない時、システムは/arbitrage-data/rawに対して空の内容を返す
5. JSONL内容を解析する時、システムは不正な行を適切にスキップして処理を続行する
6. APIレスポンスを提供する時、システムは適切なContent-Typeヘッダーを設定する

### 要件 3

**ユーザーストーリー:** システム管理者として、APIサーバーが軽量で信頼性があることを求める。これにより、アービトラージボットと並行して効率的に動作できる。

#### 受け入れ基準

1. APIサーバーを起動する時、システムは最小限の依存関係（Expressまたはネイティブhttpモジュール）を使用する
2. JSONLファイルを読み込む時、システムはメモリ効率のためストリーミングまたは行単位読み込みを使用する
3. サーバーがエラーに遭遇した時、システムはエラーをログに記録し、適切なHTTPステータスコードを返す
4. サーバーが起動する時、システムはデータディレクトリの存在を確認するか作成する
5. 同時リクエストを処理する時、システムはスレッドセーフなファイル操作を保証する

### 要件 4

**ユーザーストーリー:** セキュリティを重視する運用者として、基本的なエラーハンドリングとログ機能を求める。これにより、システムが機密情報を露出することなく信頼性を持って動作できる。

#### 受け入れ基準

1. APIリクエストが失敗した時、システムは適切なHTTPステータスコード（404、500など）を返す
2. ファイル操作が失敗した時、システムはAPIレスポンスでファイルシステムパスを露出することなくエラーをログに記録する
3. 無効なJSON行に遭遇した時、システムはそれらをスキップして処理を続行する
4. サーバーが起動する時、システムはリスニングポートとステータスをログに記録する
5. リクエストを処理する時、システムはリクエストメソッドとパスを検証する

### 要件 5

**ユーザーストーリー:** ボット運用者として、設定可能なデータ保存場所を求める。これにより、デプロイメント設定に応じてデータファイルを整理できる。

#### 受け入れ基準

1. システムが起動する時、システムは設定可能なデータディレクトリパス（デフォルト: ./data/）を使用する
2. データディレクトリが存在しない時、システムは自動的にディレクトリを作成する
3. データパスを設定する時、システムは環境変数または設定ファイル経由で受け入れる
4. ファイルを保存する時、システムは設定されたディレクトリ内で"arbitrage.jsonl"というファイル名を使用する
5. 設定が無効な時、システムはデフォルトのデータディレクトリにフォールバックする
