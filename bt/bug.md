## 🔴 重大度: HIGH（バグ相当）

### BUG-01: `wins/losses/win_rate` が間違った概念を測定している

**ファイル**: `bt/core/backtester.py:80-88`

**現状**:

```python
pnl_step = mtm - equity  # candle毎のMTM変化
if pnl_step > 0:
    wins += 1  # ← トレード勝率ではなく「MTMが上がったcandle数」
```

`trades`はbuy/sell約定回数だが、`wins/losses`は「前candle比でMTMが増減したcandle数」。
→ `win_rate` は「グリッドトレードの勝率」ではなく「価格が有利に動いたcandle比率」になっている。

**影響**: ランキングスコアの`win_rate`項が意味をなさない。

**対応**: [ ] する / [ ] しない / [ ] 後回し

### BUG-02: グリッドの状態管理がなく、同一レベルを何度でも約定できる

**ファイル**: `bt/core/backtester.py:60-77` / `bt/core/grid_strategy.py`

**現状**:

- `buys/sells`リストが毎candle全レベルをチェックする
- buyが約定しても**リストから消えない** → 同じ価格レベルを複数candle連続で約定できてしまう
- 「どのレベルが出ている注文か」の状態管理がゼロ

**本来のグリッド取引**:

- buyが約定 → そのbuyレベルを消し、上のsellレベルに注文を追加
- sellが約定 → そのsellレベルを消し、下のbuyレベルに注文を追加

**影響**: シミュレーション全体の信頼性に関わる。トレード回数・PnLが実態と大きくずれている可能性がある。

**対応**: [ ] する / [ ] しない / [ ] 後回し

### BUG-03: `cash` がマイナスになっても取引が継続する（証拠金管理なし）

**ファイル**: `bt/core/backtester.py:65`

**現状**:

```python
cash -= fill_px * qty + fee  # cash < 0 でも止まらない
```

フューチャーズ取引なので、証拠金が尽きたら強制決済（Liquidation）が発生するはずだが、シミュレーションされていない。

**影響**: 実際にはロスカットされるような極端なパラメータが「生き残れた」と判定される可能性がある。

**対応**: [ ] する / [ ] しない / [ ] 後回し

## 🟡 重大度: MEDIUM（設計の改善余地）

### BUG-04: Validationデータが完全に未使用

**ファイル**: `bt/cli.py` / `bt/config/defaults.yaml`

**現状**:

- データを6:2:2で分割して `validation.csv` を生成する
- しかしCLIもconfigも**validationを一切使っていない**
- フロー: train → OOS の2ステップ止まり

**理想のフロー**:

```
train（探索） → validation（中間チェック・過学習早期検出） → OOS（最終確認）
```

**影響**: OOSが「最終確認」でなく「探索の一部」になっているため、OOS汚染リスクがある。

**対応**: [ ] する / [ ] しない / [ ] 後回し

### BUG-05: `range_pct`の探索範囲が1点のみ

**ファイル**: `bt/config/defaults.yaml:27`

**現状**:

```yaml
range_pcts: [0.01] # 1%のみ固定
```

`range_pct`はグリッド幅を決める最重要パラメータだが、1値しか探索していない。
BTC/USDTMのボラティリティ変動を考えると、0.3%〜3%程度は探索すべき。

**影響**: パラメータ空間を狭く探索しているため、最適解を見逃している可能性がある。

**対応**: [ ] する / [ ] しない / [ ] 後回し

### BUG-06: ランキングスコアの重みに根拠がない

### BUG-07: OOS合格基準が緩すぎる可能性
