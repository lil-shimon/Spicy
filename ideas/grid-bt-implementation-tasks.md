# Grid Bot バックテスト実装タスク（KuCoin / Python）

## 前提

- 取引所: KuCoin
- ロジック: 先物グリッドBot
- 実装言語: Python
- 目的: 以下パラメータを分析可能にする
  - 本数
  - レンジ
  - 約定失敗率
  - 最低注文量
  - レバ制約
  - OOS（未学習期間）

## Epic 1: 要件と評価軸の固定

### Task 1.1

- 対象銘柄、時間足、初期資金、テスト期間を定義する

### Task 1.2

- 取引制約を定義する（最小注文量、価格刻み、手数料、レバ上限）

### Task 1.3

- KPIを固定する（純利益率、MaxDD、PF、勝率、約定率、取引回数）

## Epic 2: データ基盤

### Task 2.1

- KuCoinからOHLCVを取得するスクリプトを実装する

### Task 2.2

- 生データ保存形式を統一する（CSV or Parquet）

### Task 2.3

- データ整形処理を実装する（欠損補完、時刻統一、異常値処理）

### Task 2.4

- BT入力用データセットを生成する

## Epic 3: OOS分割

### Task 3.1

- 時系列分割を実装する（train / validation / OOS）

### Task 3.2

- 分割比率を設定ファイル化する（例: 6:2:2）

### Task 3.3

- 分割結果の期間と件数を自動検証する

## Epic 4: グリッド戦略エンジン

### Task 4.1

- グリッド注文生成ロジックを実装する（中心価格・本数・幅・レンジ）

### Task 4.2

- ポジション管理を実装する（在庫偏り、再センター、クローズ条件）

### Task 4.3

- パラメータを外部設定化する（YAML/JSON）

## Epic 5: 約定・制約モデル

### Task 5.1

- 約定失敗率モデルを実装する（失敗率、遅延、スリッページ）

### Task 5.2

- 最低注文量・価格刻み制約を強制する

### Task 5.3

- レバ制約・証拠金制約を強制する

## Epic 6: パラメータ探索

### Task 6.1

- 探索対象を定義する（本数、レンジ、幅、失敗率、レバ）

### Task 6.2

- グリッドサーチまたはOptuna探索を実装する

### Task 6.3

- train期間で上位候補を抽出する

## Epic 7: OOS評価と採用判定

### Task 7.1

- 上位候補をOOS期間で再評価する

### Task 7.2

- 過学習判定ルールを実装する

### Task 7.3

- 最終採用パラメータを決定する

## Epic 8: レポート

### Task 8.1

- パラメータ別成績表を出力する

### Task 8.2

- 損益推移、DD推移、約定率を可視化する

### Task 8.3

- 採用/不採用理由をテキスト出力する
